EXPRESS.JS

Seminário de ADS sobre o framework web mais utilizado do ecossistema Node.js.

Definição e classificação

O que é?

Express é um framework de aplicações web Node.js minimalista e flexível, que oferece um conjunto robusto de recursos para aplicações web e mobile.

Qual problema resolve?

Simplifica o trabalho com o HTTP nativo do Node.js, oferecendo roteamento e middlewares para criar aplicações web e APIs com menos código.

Onde atua dentro de uma aplicação web? No back-end, entre o cliente e os dados.
Front-End (Cliente)HTML, CSS, JavaScript (React, etc.)
↔
Back-End (Servidor)Node.js + Express.js
Express atua aqui
↔
Banco de Dados / ServiçosMySQL, MongoDB, APIs, etc.

Origem e evolução

Criado em 2010 por TJ Holowaychuk

Inspirado no Sinatra (Ruby) para simplificar a criação de servidores HTTP no Node.js.

O problema: módulo HTTP nativo

Criar rotas apenas com Node.js puro exigia muito código repetitivo. O Express surgiu para simplificar e acelerar o desenvolvimento.

Gestão StrongLoop / IBM

A aquisição do projeto garantiu suporte corporativo para grandes aplicações comerciais.

Padrão da indústria

Atualmente é o framework web back-end mais popular e utilizado de todo o ecossistema Node.js.

Quando utilizar

APIs RESTMicrosserviçosProtótipos MVPsServiços de GatewayBackend for Frontend
É mais adequado quando o objetivo é criar back-ends e APIs rápidos de desenvolver, flexíveis e simples, evitando arquiteturas rígidas.

Ecossistema e arquitetura

Minimalista e flexível

Não impõe estrutura de pastas, ORMs ou bancos de dados específicos.

Baseado no Node.js

Herda a arquitetura do Node.js, garantindo alta performance com pouco uso de memória.

Integração com npm

Possui integração com milhares de pacotes criados pela comunidade.

Modelo de funcionamento

  1. O cliente envia uma requisição HTTP para o servidor.
  2. A requisição passa por uma "linha de montagem" de funções (middlewares).
  3. Cada middleware pode inspecionar, alterar ou interromper a requisição.
  4. A rota final processa os dados e retorna a resposta HTTP.

Principais conceitos

  • Middlewares: funções que interceptam e processam requisições antes do resultado final.
  • Roteamento (Routing): mapeamento de URIs e métodos HTTP para funções que tratam a solicitação.
  • Tratamento de erros: middlewares específicos para capturar e responder exceções de forma centralizada.

Conhecimentos prévios

JavaScript / TypeScript

Base para a lógica: arrow functions, desestruturação, arrays (map, filter) e módulos.

Node.js

Runtime que executa o Express. Importante conhecer o npm, o package.json e os módulos (require/import).

HTTP

Requisições e respostas, métodos (GET, POST, PUT, DELETE), status codes, headers e ciclo cliente-servidor.

Rotas e APIs REST (JSON)

Definem como o app responde a cada endpoint, lendo dados com req.body, req.query e req.params.

Middleware

Funções que interceptam a requisição antes da rota final: autenticação, logs e tratamento de erros.

Programação assíncrona

async/await e Promises são essenciais para banco de dados, APIs e arquivos.

Instalação e configuração

1. Pré-requisitos

Node.js 18+ e npm instalados. Confira com node -v.

2. Criar o projeto

mkdir meu-projeto
cd meu-projeto
npm init -y

3. Instalar o Express

npm install express

4. Executar localmente

node --watch index.js

Acesse http://localhost:3000 no navegador.

index.js

O código importa o Express, cria o servidor e define uma rota GET / que responde "Olá, Mundo com Express!". O app.listen mantém o servidor ouvindo na porta 3000. 

const express = require('express');
const app = express();
const port = 3000;

app.get('/', (req, res) => {
  res.send('Olá, Mundo com Express!');
});

app.listen(port, () => {
  console.log(`Servidor rodando na porta ${port}`);
});

O Express não exige estrutura fixa. Conforme o projeto cresce, é comum separar rotas, controllers e arquivos estáticos em pastas próprias.

Principais recursos

1. Roteamento

Define qual função responde a cada endereço (URL) e tipo de requisição, como GET ou POST. Também pode ter parâmetros dinâmicos, como o :id. 

app.get('/api/produtos', (req, res) => {
  res.json({ mensagem: 'Lista de produtos' })
})

app.get('/api/produtos/:id', (req, res) => {
  res.json({ id: req.params.id })
})

2. Middleware

Funções que rodam entre a requisição e a resposta. Podem ler ou alterar a requisição e, ao chamar next(), passam o fluxo adiante. 

app.use((req, res, next) => {
  console.log(req.method, req.url)
  next()
})

3. Arquivos estáticos

Permitem entregar arquivos prontos, como imagens, CSS e JavaScript, sem precisar criar uma rota para cada um. 

app.use(express.static('public'));

Pontos fortes e limitações

Pontos fortes

  • Simplicidade: é minimalista e rápido, adicionando pouca sobrecarga ao Node.js.
  • Material disponível: possui muitos tutoriais, pacotes e soluções na internet.
  • Sistema de middlewares: facilita a interceptação e o tratamento de requisições com funções intermediárias.

Limitações

  • Estrutura: por ser muito livre, não mantém uma estrutura definida, e projetos grandes podem se tornar bagunçados.
  • Código: é preciso configurar manualmente autenticação, validação, tratamento de erros e conexão com banco de dados.
  • Tratamento de erros: exige bibliotecas externas para capturar erros async/await.

Adoção no mercado

Uber, X (Twitter)

Facilita o gerenciamento de intensas demandas de tráfego, como solicitações de corridas e atualizações de feed, suportando o alto volume de requisições simultâneas.

Netflix, Airbnb

Resolve a demanda de consumo em diferentes dispositivos, buscando informações e agrupando dados para entregar o conteúdo mais leve, ideal para a tela do dispositivo do usuário.

PayPal, Mercado Livre

Os middlewares suportam a demanda de integrações com as lojas virtuais e notificações de terceiros, autenticando e formatando lotes de dados e atualizações externas antes de liberar as informações para o sistema central.

NestJS, Sails.js, Feathers.js

Atendem à demanda de padronização no desenvolvimento de software de grande escala, oferecendo padrões mais rigorosos para aplicações complexas e transferindo ao Express o gerenciamento do ciclo de vida das requisições e das rotas de rede.

Segurança

Open Redirect em res.redirect()

CVE-2024-29041 CVSS 6.1 - Médio

Descrição

O Express codifica a URL com encodeurl antes de enviá-la ao cabeçalho Location. Essa codificação pode interpretar URLs malformadas de forma inesperada, fazendo com que a validação da lista de permissão avalie um destino diferente do real.

Impacto

URLs malformadas passam despercebidas por allowlists de redirecionamento. O atacante redireciona a vítima para um site falso a partir do seu domínio: phishing e roubo de credenciais.

Versões e mitigação

Afeta o Express anterior à 4.19.2, e o 5.0.0-alpha e beta anteriores à 5.0.0-beta.3. Para mitigar:

  • Atualizar para 4.19.2 ou superior;
  • Validar a URL com new URL() antes de chamar res.location / res.redirect.

Prototype Pollution no qs (DoS)

CVE-2022-24999 CVSS 7.5 - Alto

Descrição

A biblioteca qs, usada pelo Express para interpretar query strings, não bloqueava chaves como __proto__. Isso permitia modificar o protótipo global de objetos JavaScript, alterando propriedades herdadas por todos os objetos da aplicação.

Impacto

Um atacante pode injetar payloads maliciosos via query string (?__proto__[x]=y), corrompendo globalmente o Object.prototype. Isso trava o processo Node.js, gerando negação de serviço sem exigir autenticação.

Versões e mitigação

Afeta o Express anterior à 4.17.3. Para mitigar:

  • Atualizar para 4.17.3 ou superior e rodar npm audit;
  • Usar app.set("query parser", "simple") se não precisar de objetos aninhados.

Conclusão

Express é uma solução leve e eficiente para desenvolver APIs e integração com interfaces reativas. Recomenda-se o uso para MVPs e projetos de pequeno a médio porte que buscam flexibilidade e entregas ágeis. Mas não é indicado para grandes sistemas corporativos e complexos.
